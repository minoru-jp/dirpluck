# Getting started with dirpluck

This walkthrough creates a minimal Configuration, previews the planned Archive contents, and then builds the Archive. For Configuration fields, see [Configuration guide](configuration/INDEX.md). For CLI options and Invocation Templates, see [CLI guide](cli/INDEX.md). For the trust boundary, see [Trust model](TRUST.md).

## 1. Create a Configuration

When `--config` is omitted, `dirpluck` uses `default.dirpluck` from the runtime current working directory. Save the following as `default.dirpluck`:

```toml
[about]
description = "Review package for the example project."

[pluck]
description = "Project files selected for review."
must = ["README.md", "src/", "tests/"]
ignore = [".git/", "__pycache__/", "*.pyc"]

[always.guidelines]
path = "review-guidelines"
description = "Review guidelines shared across projects."
must = ["*.md"]

[output]
path = "review.zip"
```

`pluck` describes what to collect from the Target selected at runtime. `always.guidelines` adds a fixed source on every run, and `output` declares where the Archive is written.

## 2. Prepare a Target

Suppose the same directory contains these files:

```text
.
├── default.dirpluck
├── example/
│   ├── README.md
│   ├── src/
│   │   └── main.py
│   └── tests/
│       └── test_main.py
└── review-guidelines/
    └── review.md
```

`example/` is the Target selected at runtime, while `review-guidelines/` is the fixed Always source declared in the Configuration.

## 3. Preview the result

Before writing an Archive, inspect the contents plan:

```console
dirpluck ./example/ --preview
```

For this example, the preview is:

```text
├── README.md
├── example/
│   ├── README.md
│   ├── src/
│   │   └── main.py
│   └── tests/
│       └── test_main.py
└── review-guidelines/
    └── review.md
```

The leading `README.md` is generated by `dirpluck` to describe the Archive contents.

## 4. Build the Archive

If the preview looks right, build the Archive with the same Target:

```console
dirpluck ./example/
```

The `[output]` declaration creates `review.zip`. It contains the files shown by the preview together with a generated `README.md`. For this example, that README is:

```markdown
# Archive contents

Review package for the example project.

`Scope: "..."` identifies only the selection range used to find Targets; it does not imply priority, importance, or hierarchy. Any additional meaning is stated in that Scope's description.

## `review-guidelines/`

Review guidelines shared across projects.

Files: 1

## Targets

### Scope: (unnamed)

#### Pluck

Project files selected for review.

##### `example/`

Files: 3
```

Configuration `description` values add human-facing context to the generated Archive README without changing extraction semantics.
