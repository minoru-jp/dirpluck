# Migrating to 0.16

0.16.0 is a breaking release that corrects how Always sources get their Archive identity. In 0.14.x and earlier, dirpluck derived an Archive root from an Always source's `path` and optionally added `namespace` outside it. Starting with 0.16.0, `<name>` in `[always.<name>]` defines the Archive directory, while `path` identifies only the filesystem source directory.

## The Always name defines the Archive directory

In 0.14.x and earlier, this Configuration derived `documentation/` from the source location:

```toml
[always.docs]
path = "../external/documentation"
must = ["guide.md"]
```

In 0.16.0, the same Configuration produces `docs/guide.md`. `documentation` is only the filesystem source-directory name and is not used as Archive identity.

```text
docs/
└── guide.md
```

`<name>` and `path` now have separate responsibilities. `<name>` is the Archive directory identity, while `path` is the Selection root. `path` must resolve to an existing directory, and selected files keep their paths relative to that directory beneath `<name>/`.

## Always Namespace is removed in 1.0

In 0.14.x, an Always Namespace prefixed the filesystem-derived source root:

```toml
[namespace.reference]

[always.docs]
path = "../external/documentation"
namespace = "reference"
must = ["guide.md"]
```

During the 0.x series starting with 0.16.x, `namespace = "reference"` is accepted only as pre-1.0 compatibility and acts as a name override. After name resolution, the Configuration above proceeds under the new placement rules as though its effective Always name were `reference`, producing `reference/guide.md`. The old `reference/documentation/guide.md` placement is not preserved. Because this `namespace` field is removed in 1.0.0, migrate by writing the desired Archive directory name directly in the Always identifier, for example `[always.reference]`.

Loading an Always `namespace` always reports public `AlwaysMigrationWarning`. The warning states that the field is removed in 1.0.0 and points to using the Always identifier directly as the replacement. It is reported from 0.16.0 through releases before 1.0.0; in 1.0.0, both acceptance of the field and the warning are removed.

## Migration checklist

For new Configurations that do not use Namespace, write the desired Archive directory name directly as the Always name:

```toml
[always.reference]
path = "../external/documentation"
must = ["guide.md"]
```

Always effective names and Runtime Target final Archive roots are compared as Archive destination regions. An Always source that uses a Namespace override is evaluated under its overridden name. A Target and an Always source with exactly the same spelling, such as `app` and `app`, may intentionally compose into one destination region. A case-only mismatch such as Target `App` with Always `app` is ambiguous and is an error. Target/Target and Always/Always root identities must remain unique under case-insensitive comparison. Actual entry collisions inside a shared region are still detected normally by the Archive planner.

dirpluck does not reimplement host-OS-specific filename rules such as Windows reserved names or trailing-dot restrictions for Always / Namespace names. It does reject `/` and `\` because they can be interpreted as path separators and break the one-Archive-component boundary, and it rejects ASCII control characters U+0000 through U+001F plus U+007F to avoid truncating Archive entry names or corrupting display output. When moving an Archive to another OS or filesystem for extraction, users must verify that other names are valid there and are not treated as identical. To avoid common extraction collisions, dirpluck's own Archive-identity uniqueness comparison is case-insensitive.

## Migration warnings detect actual layout changes

From 0.16.0 through the release immediately before 1.0.0, dirpluck compares the valid 0.14.x Always Archive identity with the 0.16.x effective Always name. It reports `AlwaysMigrationWarning` only when the roots differ, and the warning message includes both the old and new roots.

For example, `[always.docs] path = "docs"` has `docs/` in both versions and does not emit a layout migration warning. `[always.docs] path = "documentation"` changes from `documentation/` to `docs/` and does emit the warning. Python API users receive it through the standard warnings framework; the CLI renders the same diagnostic to stderr.

Starting in 0.17.0, an Always source with an explicit effective Layout does not report this 0.14.x → 0.16.x layout migration warning. Once Layout intentionally determines the current final Archive destination, reporting the intermediate 0.16.x placement would disagree with the actual Archive path. Always sources without Layout keep the existing comparison and warning behavior.

The pre-1.0 compatibility warning for `namespace` is independent of this comparison. Using Namespace reports its removal in 1.0.0 and the replacement regardless of the Archive-layout comparison result.

## Case syntax moves to the top-level namespace

The canonical Pluck Case syntax moves from `[pluck.case.<name>]` to `[case.pluck.<name>]`. Always Case is added as `[case.always.<name>]` and selects participating sources from the effective Always-source set with either `include` or `exclude`. `include = []` explicitly selects zero Always sources.

```toml
[case.pluck.audit]
must = ["documents/", "records/"]

[case.always.release]
include = ["docs", "license"]
```

From 0.16.0 through releases before 1.0.0, legacy `[pluck.case.<name>]` remains accepted as compatibility input and reports `ConfigurationDeprecationWarning` pointing to `[case.pluck.<name>]`. Defining the same Case name in both syntaxes in one Configuration document is an error to avoid ambiguity. Legacy `[pluck.case.<name>]` is removed in 1.0.0.

The Runtime Case selector is also two-axis: `--case audit` selects only the Pluck Case, `--case .release` only the Always Case, and `--case audit.release` both. This separation means the presence of Always sources does not change whether a Pluck Case is visible.
