# Migrating to 0.17

0.17.0 adds Layout for explicitly controlling placement inside the Archive and, at the same time, makes final Archive-root uniqueness consistent across all source roles. This is a breaking release. In 0.16.x, a Target and an Always source could share exactly the same spelling of a root and compose into the same destination region. In 0.17.0, sources that resolve to the same final Archive root are an error regardless of whether they are Targets or Always sources.

## Target and Always no longer compose at the same root

In 0.16.x, for example, selecting runtime Target `./app/` together with `[always.app]` could place both under `app/`.

```toml
[always.app]
path = "support/app"
must = ["notes.md"]

[pluck]
must = ["src/"]
```

With `./app/` selected, 0.16.x could produce an Archive like this as long as the entries from the two sources did not collide directly:

```text
app/
├── notes.md
└── src/
    └── main.py
```

0.17.0 no longer permits that shared destination region. Every source must have a unique final Archive root. If a Target and an Always source both resolve to `app`, Configuration / resolution fails. Roots that differ only by case continue to be treated as the same root and are also errors.

## Separate destination regions with Layout

The recommended migration is to use Layout to give source roles separate top-level directories. A Layout must be declared with `[layout.<name>]`; its `description` is optional.

```toml
[about]
always_layout = "dependencies"
targets_layout = "development-targets"

[layout.dependencies]
description = "Fixed materials required for development."

[layout.development-targets]
description = "Development targets selected for this run."

[always.app]
path = "support/app"
must = ["notes.md"]

[pluck]
must = ["src/"]
```

Selecting the same `./app/` Target now produces distinct final Archive roots, `dependencies/app/` and `development-targets/app/`:

```text
dependencies/
└── app/
    └── notes.md
development-targets/
└── app/
    └── src/
        └── main.py
```

`[about].always_layout` and `[about].targets_layout` are defaults. Individual sources can override them with `[always.<name>].layout`, `[scope].layout`, or `[scope.<name>].layout`. A source with neither an individual Layout nor an applicable default is placed directly under the Archive root as before.

## Renaming an Always source is also a valid migration

Instead of using Layout, you can separate roots by changing the Always name itself.

```toml
[always.support-app]
path = "support/app"
must = ["notes.md"]
```

This produces separate `support-app/` and Target `app/` roots. Layout does not select a source filesystem directory; it declares the top-level Archive destination. Every referenced Layout name must have a corresponding `[layout.<name>]` declaration. An undefined Layout reference is an error. An empty `[layout.<name>]` table is valid, and placement works without a `description`.

## Namespace and the legacy migration warning

Layout in 0.17.0 is not composed with Namespace. It is an error when an effective Layout and `namespace` are both active for the same Scope, or when a compatibility Always `namespace` and an effective Layout are both active. Namespace is increasingly a compatibility surface on the path toward removal in 1.0.0, so new placement designs should use Layout.

The Always layout migration warning inherited from 0.14.x is not reported for an Always source that has an explicit Layout effective in 0.17.0. An explicit Layout intentionally determines the final Archive destination, so reporting the intermediate 0.16.x placement as a migration warning would conflict with the current output. Legacy Configurations that do not use Layout continue to receive the existing 0.14.x to 0.16.x migration warning.
